# Configuration reference

pixelagents reads one JSON file (`pixelagents.config.json`; the server writes it back when you change
settings in the web UI through `PUT /api/config`). Every key has a default (`DEFAULT_CONFIG` in
`packages/protocol`), so a config only lists what it changes. The tables below are generated from
`CONFIG_SCHEMA` by `npx tsx scripts/gen-config-docs.mjs`; the schema is also served at `GET /api/schema`.

How layers combine: plugin `defaults` go under the user's config. Objects merge key by key, scalars
and arrays replace, except the list-valued `classify`, `effects` and `assets`, which concatenate
(deduplicated) so a plugin can add rules without hiding yours.

Matching rules (`classify[].match`): every key is a path into the entity (`kind`, `id`, `status`,
`labels.host`, `metrics.depth`, ...); the value is a glob (`*` any run, `?` one character), a
`/regex/`, or a list meaning "any of". Every matching rule applies, in order; later ones win.
Strings in `set` are templates: `{{labels.host}}`. Paths in `set` are written into the entity
(`view.behavior`, `view.skin`, `view.group`, `view.hidden`, or any label path).

## Effects

`effects` is an ordered list; each entry puts one filter on one layer (`world`, `actors`, `ui`,
`screen`). Filters come from the engine (`none`, `pixelate`, `tint`, `vignette`) or from client
plugins (the `effects` plugin adds `crt`, `daynight`, `glow`, `scanlines`, `palette`, `outline`).
Unknown or `enabled: false` entries are skipped. Parameters of each filter: see "Filters" in
[plugins.md](plugins.md).

```json
{ "effects": [
  { "layer": "world",  "filter": "daynight", "params": { "hour": 22 } },
  { "layer": "world",  "filter": "glow" },
  { "layer": "actors", "filter": "outline", "enabled": true }
] }
```

## Custom plugin settings

`pluginConfig.<plugin name>` is free-form and reaches the plugin's code; each plugin documents its keys.
